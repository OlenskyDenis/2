**Гілка**: `001-bond-yield-analyzer` | **Дата**: 2026-09-24 | **Специфікація**: [spec.md](file:///d:/2/specs/001-bond-yield-analyzer/spec.md)

## 1. Резюме (Summary)

Створення автономного інструменту на Python для автоматизованого отримання ринкових даних щодо державних облігацій України (ОВДП) із сервісу Приват24 (`next.privat24.ua`).

Інструмент виконує реверс-інжиніринг публічних API-ендпоінтів Приват24 (отримання гостьової сесії, переліку всіх випусків, точних залишків паперів у наявності для купівлі та повного календарного графіку виплат купонів і погашень). Усі зібрані дані агрегуються та синхронізуються у локальний файл Microsoft Excel (`bonds.xlsx`), організований як база даних із трьома аркушами (`Актуальні котирування`, `Історія котирувань`, `Графік виплат`) з автоматичними фільтрами та недеструктивним оновленням (upsert), що виключає втрату історичних даних. Для максимальної зручності користувача на платформі Windows надається файл швидкого запуску [`run.bat`](file:///d:/2/run.bat).

## 2. Технічний контекст (Technical Context)

- **Мова та версія**: Python 3.10+ (робоче середовище: Python 3.12.10).
- **Основні бібліотеки (Dependencies)**:
  - `requests` (версія 2.31+) — взаємодія з HTTPS API Приват24, автоматичне керування сесіями та cookies.
  - `openpyxl` (версія 3.1+) — генерація, читання, недеструктивне оновлення та стилізація книг Excel (`.xlsx`), налаштування автофільтрів.
  - `pytest` (версія 8.0+) — автоматизоване модульне, контрактне та інтеграційне тестування за методологією TDD.
- **Сховище даних (Storage)**: Локальний файл Microsoft Excel (`bonds.xlsx`) з транзакційним механізмом збереження (запис у тимчасовий файл `.bonds.xlsx.tmp` з наступним атомарним перейменуванням `os.replace()`).
- **Тестування (Testing)**: Набір тестів у каталозі `tests/` (`tests/unit/`, `tests/contract/`, `tests/integration/`) під керуванням фреймворку `pytest`.
- **Цільова платформа (Target Platform)**: Пріоритетно Windows 10/11 (з ярликом/скриптом запуску `run.bat` у 1 клік), а також Linux та macOS (кросплатформна сумісність шляхів та системних викликів).
- **Тип проекту (Project Type)**: Автономна модульна бібліотека (`src/bond_collector/`) з інтерфейсом командного рядка (`src/cli/main.py`) та пакетним скриптом для користувача (`run.bat`).
- **Продуктивність (Performance Goals)**:
  - Повний цикл збору даних для ~40 випусків ОВДП (включаючи запити списку, залишків з затримкою 50–100 мс jitter та графіків виплат) триває менше 5 секунд.
  - Обробка та атомарний запис у Excel триває менше 1 секунди.
- **Обмеження та надійність (Constraints & Reliability)**:
  - Недеструктивне оновлення: раніше завантажені випуски та минулі дати виплат ніколи не видаляються.
  - Захист від пошкодження файлу Excel: транзакційний запис; при відкритому у зовнішній програмі файлі `bonds.xlsx` перехоплюється виняток `PermissionError`, виводиться зрозуміле попередження українською мовою у `stderr` і повертається код `1`.
  - Відсутність дублювання записів історії при багаторазовому запуску скрипта протягом однієї доби.

**Обґрунтування структури (Structure Decision)**:
- Каталог `src/bond_collector` є самодостатньою бібліотекою, що реалізує принцип Library-First. Будь-який інший модуль чи майбутній аналітичний модуль (наприклад, розрахунок кривих доходностей чи веб-інтерфейс) зможе імпортувати `CollectorService` або `Bond` без залучення CLI чи Windows-специфічного коду.
- Каталог `src/cli` відповідає за перетворення аргументів командного рядка, форматування інформаційного та машиннозчитуваного JSON-виводу і маршрутизацію потоків `stdout`/`stderr`.
- Файл `run.bat` забезпечує виконання вимоги користувача щодо максимальної легкості запуску у Windows через подвійний клік без ручного відкривання командного рядка.

## 5. Відстеження складності (Complexity Tracking)

*Порушень принципів Конституції не виявлено. Архітектура відповідає принципу YAGNI та правилу мінімальної необхідної складності.*

| Компонент / Рішення | Чому обрано | Відхилена альтернатива та причина |
|---|---|---|
| Збереження безпосередньо в Excel (`openpyxl`) | Пряма вимога замовника мати робочий `.xlsx` файл для подальшої фільтрації та аналізу | Використання SQLite / PostgreSQL: відхилено, оскільки створило б непотрібний проміжний шар та ускладнило б користування для нетехнічного користувача. |
| Прямий HTTP-клієнт (`requests`) | Швидкість (<5 сек), низьке споживання ресурсів, надійне отримання лімітів через публічний API | Selenium / Playwright: відхилено через важкість браузерних драйверів, тривалий запуск (>30 сек) та схильність до збоїв. |
