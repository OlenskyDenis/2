# Контракт API: Приват24 (Публічний API ОВДП)

## Загальний опис

Даний документ регламентує контракт взаємодії між модулем збору даних `Privat24Client` та публічними незахищеними кінцевими точками (endpoints) веб-сервісу Приват24 (`next.privat24.ua`).

- **Базовий хост**: `https://next.privat24.ua`
- **Протокол**: HTTPS / JSON
- **Автентифікація користувача**: Не потрібна (використовується публічна сесія гостя через токен `xref` та cookie `pubkey`).
- **Таймаут за замовчуванням**: 15 секунд на запит.
- **Політика пауз (Jitter)**: 50–100 мс випадкової затримки між запитами лімітів та графіків виплат.

---

## 1. Ініціалізація гостьової сесії

### Запит
- **Метод**: `POST`
- **Шлях**: `/api/p24/init`
- **Заголовки**:
  ```http
  Accept: application/json, text/plain, */*
  Content-Type: application/json
  User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36
  ```
- **Тіло запиту**: `{}` (порожній JSON-об'єкт)

### Відповідь (HTTP 200 OK)
- **Заголовки відповіді**: `Set-Cookie: pubkey=...; Path=/; Domain=.privat24.ua; Secure; HttpOnly`
- **Тіло відповіді**:
  ```json
  {
    "xref": "3d50df06a928929b959828d1c9ef0052ad40d346ff2e008aaae273dbdeedcf29",
    "base_url": "api/p24/pub/"
  }
  ```
- **Правила валідації**:
  - `xref` (string, обов'язковий): hex-рядок довжиною 64 символи.
  - `base_url` (string, обов'язковий): відносний шлях для публічних ендпоінтів, зазвичай `"api/p24/pub/"`.
  - Cookie `pubkey` зберігається у сесії `requests.Session` автоматично.

## 2. Отримання списку котирувань ОВДП (`bargaining`)

### Запит
- **Метод**: `POST`
- **Шлях**: `/{base_url}bonds` (наприклад, `/api/p24/pub/bonds`)
- **Тіло запиту**:
  ```json
  {
    "action": "bargaining",
    "xref": "{xref}"
  }
  ```

### Відповідь (HTTP 200 OK)
- **Тіло відповіді**: JSON-масив об'єктів облігацій або JSON-об'єкт із масивом у полі `bonds`:
  ```json
  [
    {
      "isin": "UA4000227185",
      "name": "Військові облігації",
      "currency": "UAH",
      "term": "2027-05-26",
      "priceBuy": 1056.23,
      "priceSell": 995.10,
      "rateBuy": 14.85,
      "rateSell": 17.50,
      "nominal": 1000.0,
      "issueDate": "2023-05-24",
      "active": true
    }
  ]
  ```
- **Правила валідації**:
  - Масив містить 0 або більше елементів.
  - Поля `isin`, `currency`, `term` є критичними для ідентифікації облігації.
  - Цінові та відсоткові поля парсяться як числа з плаваючою крапкою або `None`, якщо котирування відсутнє.

## 3. Отримання залишків на складі (`limits`)

### Запит
- **Метод**: `GET`
- **Шлях**: `/{base_url}bonds?action=limits&xref={xref}&isin={isin}&operation=s`
- **Параметри запиту (Query Params)**:
  - `action`: `"limits"` (обов'язково)
  - `xref`: токен сесії (обов'язково)
  - `isin`: ідентифікатор облігації, наприклад `"UA4000227185"` (обов'язково)
  - `operation`: `"s"` (критично обов'язково — запит лімітів продажу клієнту без потреби авторизації)

### Відповідь (HTTP 200 OK)
- **Тіло відповіді**:
  ```json
  {
    "isin": "UA4000227185",
    "count": 85217,
    "minAmount": 1,
    "maxAmount": 85217,
    "active": true
  }
  ```
- **Спеціальні випадки**:
  - Якщо випуск розпродано (наявність 0): `count: 0`, або `active: false`, або `maxAmount: 0`.
  - У клієнтській моделі `Bond.available_qty` приймає значення `int(count)`. Якщо `count` відсутній або дорівнює 0, фіксується `0`.

## 4. Отримання графіку купонів та погашення (`operations`)

### Запит
- **Метод**: `POST`
- **Шлях**: `/{base_url}bonds`
- **Тіло запиту**:
  ```json
  {
    "action": "operations",
    "xref": "{xref}",
    "isin": "{isin}"
  }
  ```

### Відповідь (HTTP 200 OK)
- **Тіло відповіді**:
  ```json
  {
    "isin": "UA4000227185",
    "operations": [
      {
        "date": "2024-11-20",
        "type": "KUPON",
        "amount": 75.50,
        "currency": "UAH"
      },
      {
        "date": "2025-05-21",
        "type": "KUPON",
        "amount": 75.50,
        "currency": "UAH"
      },
      {
        "date": "2027-05-26",
        "type": "PAYMENT",
        "amount": 1000.0,
        "currency": "UAH"
      }
    ]
  }
  ```
- **Правила мапінгу типів подій**:
  - `"KUPON"` / `"COUPON"` -> `Купон`
  - `"PAYMENT"` / `"REPAYMENT"` / `"NOMINAL"` -> `Погашення`

## 5. Обробка помилок та статусів

| Код / Стан | Причина | Дія клієнта |
|---|---|---|
| HTTP 403 / 401 | Закінчився термін дії `xref` або сесії | Автоматичний повтор ініціалізації сесії (`init`) і повтор запиту (до 2 спроб). |
| HTTP 500 / 502 / 503 | Тимчасовий збій серверів банку | Retry з експоненційним бекофом (1с, 2с). При невдачі — вивід у `stderr` і безпечне завершення з кодом 1. |
| Timeout (> 15c) | Мережева затримка | Повторний запит. Якщо повторний запит провалився — вивід діагностичного повідомлення. |
| Помилка `limits` для окремого ISIN | Банк не має даних по лімітах для конкретного паперу | Логування попередження у `stderr`, встановлення `available_qty = 0`, продовження циклу для інших облігацій. |
